# Fichiers tenus hors d'opcache sur un poste de developpement.
#
# Un chemin qui se termine par « / » couvre tout le repertoire. Ce qui est
# liste ici n'est jamais mis en cache : PHP le recompile a chaque requete, et
# une modification est donc visible au simple rechargement de la page.
#
# La liste tient en une entree, et c'est voulu. Elle a d'abord couvert tout le
# code du projet — `app/`, `routes/`, `database/`, le module — ce qui rendait
# bien toute modification immediate, mais faisait recompiler 272 fichiers a
# chaque requete depuis un montage venant de l'hote :
#
#     tout le code du projet hors cache      0,35 s par requete
#     les seuls gabarits compiles            0,15 s par requete
#
# Les gabarits compiles, eux, ne coutent presque rien a exclure : ils vivent
# dans le volume `keneya_storage`, pas sur le montage, et il n'y en a qu'une
# soixantaine.
#
# C'est aussi le seul endroit ou le piege se refermait vraiment : Laravel
# recompile bien un gabarit modifie, mais sous le meme nom de fichier, et
# opcache ne le voyait pas. Une classe modifiee, elle, se remarque tout de
# suite — l'ecran ne change pas du tout, la ou un gabarit perime donne
# l'illusion d'avoir enregistre.
#
# Regle : gabarits, styles et images sont visibles au rechargement ; une
# modification de classe, de route, de configuration ou de `vendor/` demande
# un `docker compose restart app`.
#
# Ce fichier n'est monte que par `docker-compose.yml`, la pile de
# developpement. Un deploiement en service ne le voit pas.
/var/www/html/storage/framework/views/
